# QQ 宠物唯一产品契约

> 冻结日期：2026-08-21
> 依据：`2026-08-21-full-project-audit-and-roadmap.md`
> 适用范围：OneBot 群、QQ 官方群、QQ 官方频道
> 当前前提：项目尚未上线，本契约不要求兼容生产数据

## 1. 不再变动的产品决策

1. 玩家熟悉的宠物养成是主循环；远征、图鉴和社区是增量玩法，不能替代签到、背包、商店和互动。
2. `PlayerAccount`、`PlayerIdentity`、`PetProfile`、`GlobalInventoryItem`、`PlayerWallet` 是唯一账号、宠物、背包和钱包模型。
3. 所有平台进入同一命令路由和同一领域服务。平台只负责事件标准化和消息能力渲染。
4. `宠物菜单`、`领养宠物`、`我的宠物`、`签到`、`我的背包`是主命令；`菜单`、`状态`、`今日`、`背包`只作为隐藏兼容别名。
5. 旧玩法默认恢复或重做。任何玩法只有在单独产品决策后才能删除，不能用“新版、旧版、下线、升级为远征”等文案代替功能。
6. OneBot 同一个 QQ 身份跨群共享账号；QQ 官方身份按网关提供的群或频道场景隔离，玩家可通过绑定码合并身份。
7. 项目尚未上线，最终切换时直接重建 SQLite；不保留双写、旧表兼容层或历史迁移代码。

## 3. 唯一玩法目录

| 玩法域 | 产品决定 | 唯一数据写入口 | 验收条件 |
|---|---|---|---|
| 账号与身份 | 保留 | AccountService | 并发解析不产生孤儿账号；绑定可合并跨平台身份 |
| 宠物档案 | 保留并补齐 | PetService | 领养、状态、商店、互动读取同一 `PetProfile` |
| 钱包 | 新建 | WalletService | 原子收支，任何扣款后余额不为负 |
| 背包 | 保留统一模型 | InventoryService | 原子增减/转移，任何扣减后数量不为负 |
| 签到 | 恢复旧配置能力 | DailyService | 奖励表驱动；签到、宠物、钱包、背包同一事务且每日仅一次 |
| 商店与物品 | 恢复 | ShopService、ItemEffectService | 购买、出售、使用形成经济闭环 |
| 日常陪伴 | 恢复 | CompanionService | 配置驱动，变化可解释，不写旧表 |
| 学习/锻炼/健身/打工 | 重做 | ActivityService | 统一 `ActivityRun`，开始与结算幂等 |
| 进化与觉醒 | 恢复 | EvolutionService | 条件可预览，消耗与形态更新同一事务 |
| 远征 | 保留增量 | ExpeditionService | 模板驱动、单活跃、奖励快照、幂等领取 |
| 图鉴 | 保留增量 | CodexService | 所有授予引用 `CodexCatalogConfig` |
| 社区/小队/首领/求助 | 保留增量 | CommunityService | 与统一账号和背包事务一致；并发不覆盖进度 |
| 活动与奖励轨道 | 保留并补齐 | EventService | 里程碑可幂等发奖 |
| 钓鱼/抽奖/对抗/交易 | 重做后恢复 | 独立扩展服务 | 概率、保底、次数、风控、审计均可验证 |
| 家族 | 重做 | Community 子域 | 不恢复旧 `Family` 表链路 |

## 4. 平台能力契约

| 能力 | OneBot 群 | QQ 官方群 | QQ 官方频道 | 产品规则 |
|---|---|---|---|---|
| 标准文本命令 | 必须 | 必须 | 必须 | 同一命令目录和同一业务结果 |

| 图片 | 本地文件或 URL | 媒体上传 | 频道能力适配 | 失败记录阶段、时间和请求信息，不暴露给玩家 |
| Markdown | 平台适配 | 能力开启时 | 能力开启时 | 后台只展示实际可用能力 |

## 5. 配置生效真值表

状态说明：`已接入`可以在当前运行时追踪到消费者；`迁移中`仍有旧消费者或部分硬编码；`未生效`不得在后台显示“已生效”。

| 配置模型 | 当前消费者 | 影响的玩家操作 | 状态 |
|---|---|---|---|
| CommandConfig | `core.RebuildUnifiedRouter` | 命令触发词与启停 | 已接入；菜单/示例动态化迁移中 |
| MenuConfig | `handleHelp` 的专题帮助 | 帮助专题 | 迁移中，主菜单尚未完全动态生成 |
| PetSpeciesConfig | PetService、领养列表/图片解析 | 领养初始属性、形态与图片 | 基础字段已接入；进化/觉醒迁移中 |
| ItemConfig | 旧物品处理器 | 查看物品、使用、互动效果 | 迁移中 |
| ShopItemConfig | 旧商店处理器 | 商店、购买、出售 | 迁移中 |
| CheckinRewardConfig | DailyService | 签到货币、好感、物品和图片 | 已接入统一事务 |
| WorkSettingConfig | ActivityService | 打工岗位、时长、消耗与奖励 | 已接入统一 ActivityRun |
| LiveEventConfig | EventService / CommunityService | 活动名称、区域、选项、进度周期和社区影响 | 已接入 |
| RewardTrackConfig | EventService | 活动里程碑幂等发奖与补领 | 已接入 |
| GrowthRoleConfig | `gameplayrules.EnabledRoles` | 定位与技能组 | 已接入；技能解锁迁移中 |
| GrowthStanceConfig | `gameplayrules.EnabledStances` | 编队姿态 | 已接入；结算影响迁移中 |
| PersonalityRuleConfig | `gameplayrules.ResolveTrait` | 陪伴行为形成性格 | 已接入 |
| CodexCatalogConfig | `gameplayrules.EnabledCodexEntries` / ExpeditionService | 图鉴目录与远征授予校验 | 已接入 |

新增或修改后台配置必须同时提供：消费者函数、影响命令、有效修订号、模拟用例。找不到消费者时，只能标记“未接入”，不能标记“已生效”。

## 6. 玩家文案规范

玩家回复以“旧版的丰富度与欢快氛围”为最低体验基准，并按场景分层：

- 领养、签到、互动、进化、远征归来和稀有奖励应包含结果、真实变化、宠物或场景反应、现有配图以及一到两个下一步命令；
- 状态、背包、商店、图鉴和社区列表应优先保证层次清楚，再加入简短的世界观包装；
- 输入错误和条件不足应说明原因并给出正确操作，不用庆祝语气；
- 隐私、删除、二次确认和技术故障必须严肃克制；
- 群聊与频道中的每条回复必须通过平台原生艾特、昵称前缀或引用关系明确指向操作者，私聊不重复艾特。

禁止玩家侧出现：

- 新版、旧版、下线、迁移、固定进度、不含抽奖；
- 平台额度、接口、数据库、内部账号、UUID、配置未加载；
- SQL、HTTP、文件路径、Go 原始错误和 `err.Error()`；
- 限额策略、强制考勤、低压力设计、自动结算策略。

统一格式：

- 标题使用 `【结果】`；
- 数量使用 `物品 ×2`，数值变化使用 `好感 +3`；
- 命令使用中文引号，例如 `发送“我的宠物”`；
- 主菜单使用少量稳定 Emoji 分区，不在每一行堆叠装饰；
- 成功回复只推荐主命令，不推荐 `今日`、`状态` 等隐藏别名；
- 业务错误说明缺少什么及下一步；技术错误统一为“刚才没有处理成功，请稍后再试”。

## 7. 变更门禁

1. 菜单出现的每个功能必须有启用的独立处理器和成功/输入错误/条件不足/系统错误测试。
2. 新命令必须拥有稳定功能 ID、主命令、别名、平台范围和玩法状态。
3. 同一个触发词只能属于一个功能；注册冲突必须阻止启动。
4. 只有替代玩法通过三平台契约测试后，才能删除旧处理器和旧回退。
5. 最终切换前必须证明 `UserPet`、`BackpackItem`、`Family` 的运行时引用为零，再从迁移模型和数据库中移除。
6. 玩家文案禁用词扫描、SQLite 并发测试、Go/前端测试和真实集成测试均为发布门禁。
