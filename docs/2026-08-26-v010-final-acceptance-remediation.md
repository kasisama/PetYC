## 3. 整改一：重做平衡模拟器

### 3.1 当前问题

当前文件：

```text
tools/simulate_season.go
```

模拟器虽然读取了 `config/defaults/config_v0.1.0.json`，但部分关键结果由目标值直接约束：

- 标准玩家收入通过 `clamp(..., 250, 350)` 被强制夹进目标区间。
- 标准玩家消耗通过固定区间限制。
- 进化判定直接限定在第 7–12 天。
- 觉醒判定直接限定在第 35–49 天。
- 装备更换间隔直接写成 `4 / 8 / 14`。

这会导致“目标通过”成为模型前提，而不是模拟结论。

### 3.2 正确整改目标

模拟器必须继续满足：

- 读取真实 `config/defaults/config_v0.1.0.json`。
- 固定种子，默认 `20260826`。
- 10,000 名玩家。
- 70 天。
- 低活跃、标准活跃、高活跃三类玩家。
- 输出 JSON、CSV、Markdown。

但必须移除以下写法：

- 为了达标而把收入/消耗直接夹到目标区间。
- 为了达标而直接固定进化、觉醒日期窗口。
- 为了达标而直接固定装备更换周期。
- 用最终目标值反推模拟事件日期。

### 3.3 建议模型

#### 每日行为

从配置派生每类玩家的行为次数与收益：

- 签到：读取 `checkin_rewards`。
- 打工：读取 `work_settings`，按可用时间选择档位。
- 常规商店：读取 `shop_items`，根据饱食、互动和活动需求产生购买行为。
- 探索：读取区域等级、消耗、掉落池和探索活跃率。
- 远征：读取远征时长、消耗、经验和掉落池。
- 首领：读取首领窗口、推荐等级、奖励档位。
- 赛季：读取奖励轨和赛季商店。

活跃度只允许控制：

- 每日在线分钟数。
- 每种行为的参与概率。
- 风险偏好或资源储蓄倾向。

不得直接控制最终收入、进化日、觉醒日和换装日。

#### 货币

主货币收入必须由实际行为累加：

```text
签到收入 + 打工收入 + 探索货币掉落 + 活动奖励
```

主货币消耗必须由实际购买、制造、互动等事件累加。

`journey_badge` 与 `season_token` 同样必须从真实掉落和奖励轨获得，再按商店购买逻辑消耗。

#### 等级

等级只能根据 `adventure_levels.xp_to_next` 和实际探索/远征经验推进。

#### 进化

进化判定必须读取：

- `pet_evolution_rules.required_growth`
- `required_affection`
- 进化消耗材料
- 材料库存
- 当前形态

达到全部条件的那一天才记录为进化日。

#### 觉醒

觉醒日期必须来自实际成长、好感和觉醒材料库存，不得直接限定在第 35–49 天。

分支选择可以基于玩家偏好或随机种子，但不得使用纯随机锁死不可逆路线。

#### 装备更换

装备更换必须由以下因素决定：

- 获得的新装备战力高于当前装备。
- 制造材料和蓝图已满足。
- 当前等级达到装备要求。
- 对应槽位确实发生替换。

记录相邻两次真实替换的日期差，最后计算前/中/后期 P50。

### 3.4 模拟器必须输出的指标

- 各活跃度玩家数量。
- 每日主货币收入、消耗、净流入。
- 第 70 天货币余额 P10/P50/P90/P99。
- `journey_badge` 产出、消耗和余额。
- `season_token` 产出、消耗和余额。
- Lv.2–25 到达人数和 P50 日期。
- 标准进化人数、成功率、日期分布。
- 觉醒人数、成功率、日期分布。
- 12 区域解锁人数和 P50 日期。
- 前/中/后期真实装备替换间隔。
- 材料库存 P10/P50/P90/P99。
- 首领参与率、完成率、贡献 P50/P90。
- 稀有掉落 P50/P90/P99。
- 保底触发率。
- 五条谱系战斗表现。
- 五条谱系远征表现。
- 最强/最弱谱系比值。

### 3.5 达标标准

目标只能用于最后判断，不能参与生成结果：

- 标准玩家日收入 P50：250–350。
- 标准玩家日消耗 P50：180–280。
- 标准进化日 P50：7–10 天。
- 觉醒日 P50：35–49 天。
- 装备替换 P50：
  - 前期 3–5 天
  - 中期 7–10 天
  - 后期约 12–16 天
- 五谱系表现比值建议不超过 1.15。
- 不允许一个谱系同时在战斗、远征和生存三个维度第一。

如果模拟未达标，应调整 `tools/generate_v010.go` 或默认数据，再重新生成配置和重跑模拟；不得把结果夹回目标区间。

### 3.6 模拟器回归测试

建议新增针对模拟核心函数的测试：

1. 商店价格提高后，标准玩家消耗或购买次数发生变化。
2. 签到和打工收入降低后，日收入明显下降，而不是仍被夹在 250–350。
3. 进化成长要求提高后，进化日期推迟或成功率下降。
4. 移除觉醒材料来源后，觉醒成功率显著下降或归零。
5. 装备掉落减少后，更换间隔增加。
6. 修改等级经验曲线后，到达等级日期发生变化。
7. 相同种子和配置输出一致。

## 4. 整改二：工作簿公式与完整视觉验收

### 4.1 当前问题

文件：

```text
docs/operations-v0.1.0.xlsx
tools/generate_workbook.py
tools/render_workbook.py
```

当前工作簿已经具备：

- 242 个公式。
- 表头、冻结、筛选和基本格式。
- 20 张 PNG 渲染产物。

但当前验证存在以下问题：

1. 242 个公式没有缓存计算结果。
2. `render_workbook.py` 使用 `data_only=False`，渲染的是公式文本。
3. 错误扫描只检查公式字符串里是否直接出现 `#REF!` 等字样，没有实际计算公式。
4. 渲染只取每张表前 42 行、前 12 列，不是完整工作表。
5. 这些 PNG 是自绘表格，不是 Excel/LibreOffice 实际布局渲染。

### 4.2 整改目标

必须做到：

- 公式经过一个真实电子表格计算引擎计算。
- 计算后扫描显示值中的公式错误。
- 每张工作表的实际使用区域都进入视觉验收。
- 视觉结果显示计算值，不显示公式字符串。
- 长表不能截掉后半部分。

### 4.3 推荐实现方式

优先顺序：

1. 使用 LibreOffice/Calc headless 打开并另存，完成公式重算。
2. 或使用 Microsoft Excel COM 打开、`CalculateFullRebuild`、保存。
3. 如果当前机器缺少可用计算引擎，应明确报告环境阻断，不能继续宣称“公式已经验证”。

LibreOffice 示例：

```powershell
soffice --headless --convert-to xlsx --outdir <临时目录> docs/operations-v0.1.0.xlsx
```

实际执行时避免输入输出为同一路径，可先复制到临时目录，重算后再替换正式文件。

Excel COM 示例流程：

```text
打开工作簿
设置 Calculation 为自动
执行 CalculateFullRebuild
保存
关闭 Excel 进程
```

### 4.4 公式错误扫描

重算后以 `data_only=True` 重新读取，扫描：

- `#REF!`
- `#DIV/0!`
- `#VALUE!`
- `#NAME?`
- `#N/A`
- `#NULL!`
- 空白公式缓存

验收要求：

- 公式数量大于 0。
- 所有公式单元格均有计算结果或合理的空值结果。
- 公式错误数为 0。
- 不存在外部工作簿引用。
- 不存在循环引用警告。

### 4.5 视觉验收

每张工作表必须按实际使用区域渲染。

长表可以分页，但必须覆盖全部行：

- 统一物品：全部 45 条。
- 资产需求：全部资产记录。
- 怪物、技能、装备、词条、掉落：全部记录。

每张表检查：

- 标题和表头可读。
- 关键数字没有截断。
- 中文没有乱码。
- 公式列展示数值，不展示 `=...`。
- 不存在列重叠和极端窄列。
- 颜色对比度可读。
- 冻结行和筛选范围正确。
- 不存在完全空白工作表。

如果使用分页渲染，建议文件命名：

```text
05-统一物品-p01.png
05-统一物品-p02.png
```

### 4.6 工作簿内容一致性

工作簿必须重新读取最终的：

```text
config/defaults/config_v0.1.0.json
docs/simulations/season70-10000.json
```

需要核对：

- 三货币名称、来源、消耗一致。

- 模拟结果使用整改后的非自证模拟输出。
