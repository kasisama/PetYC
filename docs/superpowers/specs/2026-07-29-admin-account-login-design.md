# 后台账号登录设计

## 目标

将后台现有的浏览器 `prompt` 管理员令牌认证改为单管理员账号登录。默认账号为 `admin`，默认密码为 `123456`；管理员登录后可以修改密码。错误凭据不会让页面陷入持续 401，用户可以直接重新输入。

## 范围

- 只提供一个固定用户名 `admin`，本次不支持修改用户名或添加多个管理员。
- “记住我”默认不勾选；勾选后登录态保持 15 天，未勾选时只在当前浏览器会话有效。
- 保留 WebSocket Token 及其现有认证方式，不再使用 Admin Bearer Token 保护后台 API。
- 不引入外部数据库表或前端构建流程。

## 架构

### 凭据存储

继续使用应用数据目录下的 `credentials.json`。凭据结构增加管理员用户名和 bcrypt 密码哈希；文件中不保存管理员明文密码。

加载旧凭据文件时，如果管理员用户名或密码哈希缺失，则自动写入用户名 `admin` 和默认密码 `123456` 的 bcrypt 哈希。现有 WebSocket Token 原样保留。凭据更新通过进程内互斥锁串行化，并使用同目录临时文件加重命名替换，避免写入中断产生半截 JSON。

### 会话

服务端维护内存会话表。登录成功后生成密码学安全的随机令牌，浏览器只通过 Cookie 持有原始令牌，服务端只保存令牌的 SHA-256 哈希。

- 未勾选“记住我”：发送无 `Max-Age` 的会话 Cookie。
- 勾选“记住我”：Cookie 和服务端会话均在 15 天后过期。
- Cookie 属性为 `HttpOnly`、`SameSite=Strict`、`Path=/`；HTTPS 请求设置 `Secure`。
- 服务重启会清空内存会话，用户重新登录即可。
- 退出登录删除当前会话并清除 Cookie。
- 修改密码成功后删除全部管理员会话并清除当前 Cookie。

### HTTP 接口

公开认证接口：

- `POST /api/admin/auth/login`：接收 `username`、`password`、`remember`。
- `GET /api/admin/auth/session`：返回当前是否已登录以及管理员用户名。

受认证保护的接口：

- `POST /api/admin/auth/logout`：注销当前会话。
- `PUT /api/admin/auth/password`：接收 `current_password`、`new_password`、`confirm_password`。
- 现有的统计、宠物、群组、补偿、配置和上传接口。

登录失败统一返回“账号或密码错误”。新密码和默认密码保持一致的最低长度约束：至少 6 个字符；受 bcrypt 限制，最多 72 个 UTF-8 字节。新密码与确认密码不一致、旧密码错误时返回明确但不泄漏存储信息的 400 响应。

## 前端交互

页面加载时首先调用会话状态接口；未登录时显示全屏登录页，不调用后台数据接口。

登录页包含账号、密码和“记住我”。复选框默认不勾选。登录失败时保留账号、清空密码、显示错误，表单保持可操作并允许立即重试。

登录成功后进入现有控制台并加载数据。顶栏新增管理员菜单，提供“修改密码”和“退出登录”。修改密码表单包含旧密码、新密码和确认新密码；成功后返回登录页，要求使用新密码重新登录。

全局请求包装器不再读取或写入管理员令牌。任何受保护接口返回 401 时，前端统一切换为未登录状态并显示登录页，避免错误凭据导致连续请求失败。

## 错误处理

- 无效 JSON 或缺少字段返回 400。
- 错误账号或密码返回 401，错误信息保持一致。
- 无效、缺失或过期会话返回 401，同时清除失效 Cookie。
- 凭据文件读写失败返回 500，并在服务端日志记录具体原因。
- 登录和改密期间禁用重复提交按钮；请求结束后恢复。

## 测试

自动化测试覆盖：

- 旧凭据文件自动补齐默认管理员账号和密码哈希。
- 默认密码可以验证，错误密码被拒绝，改密后旧密码失效且新密码生效。
- 登录成功、登录失败、会话状态查询。
- 未勾选时 Cookie 为浏览器会话 Cookie；勾选时 Cookie 有效期为 15 天。
- 缺失、无效和过期会话被后台中间件拒绝。
- 退出仅注销当前会话。
- 修改密码注销全部会话。
- 现有后台 API 继续受保护，WebSocket Token 行为不变。

最终执行 `gofmt`、`go test ./...` 和 `go build ./...`，并启动服务手工检查登录重试、记住我、修改密码、401 回退及退出流程。
